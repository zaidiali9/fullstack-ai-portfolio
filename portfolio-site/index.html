How I work

What you can expect on a project.

  • Measure, then claim

    AI features ship with an evaluation set and a before/after number. If something is weak, the write-up says so and names the next step.

  • Guardrails in the right layer

    The database prevents double bookings; a parser checks model SQL; model output never triggers privileged actions without validation.

  • Tested like users use it

    Integration tests on a real Postgres engine, end-to-end tests in a real browser, accessibility scans in light and dark mode, 360 px layouts.

  • No lock-in to one AI vendor

    A provider-agnostic AI layer runs free local models, Ollama, Groq, Gemini or a paid API, and degrades to a clear "AI unavailable" state.

  • Secure by default

    Input validation, rate limits on auth and AI, CSRF-safe forms, secure headers, authorisation on every route, no secrets in code.

  • Handover-ready

    Docker and CI, an environment table, a verification log of every claim, and a README a new developer can follow.
